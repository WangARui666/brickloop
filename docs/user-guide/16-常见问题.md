# 16 常见问题

本章你将学会：按现象排查安装、零件、颜色、文件交换和 AI 连接问题，并准备有用的反馈资料。

## Windows 提示“Windows 已保护你的电脑”

安装包没有代码签名，发布者可能显示为“未知发布者”。

1. 确认安装包是从 GitHub 的 Releases 页面下载的，版本与页面一致。
2. 在 PowerShell 中对实际文件执行 `Get-FileHash -Algorithm SHA256 <安装包路径>`，与同一版本附带的 `SHA256SUMS.txt` 比对；路径有空格时用引号包住。
3. 核对无误后，在提示中点击“更多信息 → 仍要运行”。不要为了安装关闭系统防护。
4. 如果组织策略禁止运行或没有“仍要运行”，把安装包版本和提示交给管理员处理。

SmartScreen 是 Windows 系统提示，实际样式和可用按钮随系统版本及组织策略变化。本章用上述操作步骤说明，不展示模拟系统提示。

## 搜索不到零件

1. 查看当前数据包是否选对，清除过窄的分类条件，再用乐高编号或工厂编号搜索。
2. 尝试 `2x4` 等尺寸或简短中文关键词；工厂命名可能与通用名称不同。
3. 临时切到“全部”，查看“显示全部 LDraw 零件”的结果。找到后仍需核对当前工厂能否生产。
4. 如果编号对应多个模具或印刷版本，向维护者提供具体 LDraw 文件名；基础件和印刷件不能只按一个大类编号混用。
5. 如果整个库都为空，等待加载完成后“重试”，到“设置 → 零件库”核对路径。安装包已包含零件库；仍为空时，重新安装或在 GitHub 上提交问题。

## 模型里有占位或“暂无零件图形”

先区分加载中的灰色占位与缺失形状。查看加载进度，等待后台补载；失败时可重试。加载期间允许旋转、选择与保存，保存不等待所有形状，缩略图可能稍后补写。若补载结束仍有缺失，再按下列步骤处理。

1. 按 F7 查看“缺少几何”，记录零件编号、缺失文件或依赖。
2. 核对工程所需的工厂自制件数据包。原始 STL／STEP 资料不等于已完成可显示的 `.dat` 零件。
3. 请维护者补齐资料后重新加载；保留原实例，避免误删需要的零件。
4. 形状不完整时先不要确认尺寸或三维导出结果，报告中可能已跳过缺失形状。

## 颜色为什么显示为非工厂色

1. 查看是否刚导入 Studio 文件或切换数据包；导入颜色可以保留，但不一定在当前工厂色表中。
2. 区分“非工厂颜色”与“不可生产的配色”：前者是整个色表没有，后者是该零件不能生产此颜色。
3. 在工厂色表里选择替代色，或使用 AI“换成工厂件”协助检查与替换。
4. 屏幕颜色接近不表示工厂色号相同；若工厂实测色或色号映射有误，请先修正数据包，再处理模型。

## 导出的 `.io` 在 Studio 中显示异常

1. 保留原 `.brkl`、导出的 `.io` 和“另存报告”得到的文本，记录 Brickloop 与 Studio 版本。
2. 对照报告检查颜色降级、编组注释、共享子模型隐藏状态降级，以及缺少自制件几何。
3. 在两个软件中查看相同视角，记录异常零件编号、颜色、步骤和子模型。尽量用少量零件制作能重现问题的副本。
4. 在 GitHub 上提交问题，写明预期效果、实际效果和重现步骤。不要仅发送一张无法定位零件的截图。
5. 在互操作问题核实前，继续保留 `.brkl`；如果原 `.io` 是旧版加密格式，先在 Studio 中另存或导出 `.mpd`。

## AI 连接失败或没有可用模型

1. 打开“AI 设置”，核对服务商类型、服务地址、模型名称与密钥是否正确。兼容接口使用服务商要求的地址，不要重复添加 `/v1`。
2. 点击“测试连接”。没有返回模型时，检查服务商是否提供模型列表、所选账号是否有该模型权限；测试成功仍不代表所有模型都支持工具或图片。测试请求会计入本地日期的每日费用账本；达到上限或缺少价格时先检查“用量与限制”。
3. 检查“使用系统代理”或自定义代理是否符合当前网络环境；本机服务须已启动，端口与地址正确。
4. 检查是否启用了“仅使用本机模型”。该选项会拒绝云端模型与 ChatGPT 登录；要使用云端，需由你主动关闭此限制。
5. API 方式检查余额、限流、每日费用上限与模型价格设置。显示“未配置模型价格”时先补价格，不能理解为免费。
6. ChatGPT 方式检查系统浏览器是否完成授权、应用是否显示已登录账号和可用模型；必要时退出再登录。套餐额度用尽后等待恢复或主动更换服务商，不会自动转用 API 计费。
7. 卡片显示“需要重新填写”或“需要重新登录”，或对话提示“已保存的 Key 无法读取”：说明加密凭据所用的密钥丢失，常见原因是删除了 `%LOCALAPPDATA%\Brickloop\session`。按提示重新粘贴 Key 或重新登录；之后不要删除该文件夹。清除缓存不会影响它。
8. 图片任务还要确认首次发图提示已允许，图片大小和数量未超限。需要反馈时保留脱敏错误信息，不发送 API Key 或登录令牌。

## 普通对话正常，看图搭建却失败

先读报告顶部的失败详情（0.12.2 起提供），它写明失败的阶段、原因类别、HTTP 状态码、错误代码和服务商说明。

- **请求被服务商拒绝（HTTP 400）**：常见原因是模型不支持图片输入，或者不支持图片与工具同时使用。到“按用途选择模型”中，把“视觉理解”换成支持看图的模型。
- **服务商错误、资源不足、网络中断**：软件已自动重发失败的请求（间隔从约 2 秒起逐次加倍，最多 10 次，超时类最多 3 次，服务商要求等待更久时按它要求的时间等）。稍后再试，或改用同一服务商的其他模型。已经搭好的部分会保留，可在审阅中保留或撤销。
- **余额或额度不足（HTTP 402）**：到服务商控制台充值后再试。
- **模型输出达到长度上限**：同一轮已重试仍被截断。可以减少部件数量，或把需求分成几次完成。

反馈时附上报告中的错误代码、状态码和请求 ID。

## AI 任务好像卡住了

先看任务卡或回合上的状态行，见[第 12 章](12-AI助手.md)“任务运行中：模型是否还在工作”。

1. 写着“已生成约 N 字”，并且字数在增加：模型在工作。思考模式的模型写一段长脚本可能要 2～4 分钟，请耐心等待。
2. 写着“已 N 秒没有收到数据”：服务商没有响应。先等一等；超过 10 分钟软件会自动终止并重试。
3. 等不及时点“停止”，已完成的修改会保留，进入审阅。之后可以重新发送，或换一个模型。
4. 多次出现时，检查网络和代理设置（见上文“AI 连接失败或没有可用模型”），并在 AI 设置中测试连接。

## AI 好像还记着之前失败的内容

停止和被丢弃的回合，以及失败且没有任何修改的回合，不会再发给 AI，在对话中标有“未计入上下文”。失败但已经保留了修改的回合，只把你的请求、失败原因和已完成修改的数量以摘要发给 AI，标有“已以摘要计入”。

如果连之前正常完成的讨论也想清除，点击输入框上方的“新对话”，再保存工程。模型和撤销记录不受影响。见[第 12 章](12-AI助手.md)“对话上下文与新对话”。

## MCP 看见工具但不能操作工程

1. 保持 Brickloop 已启动，并开启“允许外部智能体连接”。
2. 重新复制当前机器设置页生成的配置；安装目录变化后，旧路径可能已经失效。
3. 发起一次实际工具调用，回到 Brickloop 处理连接确认。仅列出工具不代表已经连接工程。
4. 断开后在外部客户端重新启动 MCP 会话。若使用 HTTP，核对端口和访问令牌。

## 停止 AI 后为什么还有修改

1. “停止”结束后续工作，已完成内容保留在任务结果中。文档未改动时直接应用；你在任务期间编辑过文档时，结果进入“待合并”。不需要结果可直接“丢弃”。
2. 合并后的“本轮修改审阅”提供“撤销整轮”，可撤销这一轮的修改和其后的审阅操作。
3. 如果已经追加人工编辑，按正常撤销顺序处理。外部 MCP 每次修改调用单独成一个撤销点，可能需要撤销多次。

## 为什么任务待合并，或出现冲突

任务从启动时的文档建立工作副本，AI 看不到你之后的编辑。文档期间有过编辑时，结果等待你合并；双方修改了同一实例且结果不同，会保留你的版本并列入冲突组。选择“用 AI 版本”会覆盖整个实例，选择“保留我的”不会改文档。若模型定义或步骤已被删除，需先恢复所需结构，再使用 AI 版本。

任务和工作副本只留在当前会话中，重启后不会恢复。关闭文档和退出前会提示停止并丢弃未完成任务；需要保留的结果应先合并并保存工程。

## 看图搭建达到预算，或马赛克出现悬空

1. 达到预算时先看“未完成项”，保存现有结果，再针对缺失部件追加要求。可以缩小尺寸、减少部件，或明确增加下一次任务的次数与时间预算。
2. 不要仅凭轮廓重合率决定加预算，先检查视角、背景和主体比例是否一致。
3. 马赛克只生成平面零件，不自动加底板。需要实体连通时补齐底板与连接，再运行检查。

## 应用意外退出，怎样避免覆盖旧方案

1. 重启后在“恢复未保存的文档”核对时间与路径，优先“另存为”一个新名称。
2. 打开恢复结果，核对模型和资源，再与原文件比较。不要先点“丢弃”。
3. 正常关闭时已经选择“不保存”的文档，恢复资料会被清理；这类情况需要使用已有工程备份。

## 大工程打开要多久

0.9.0 的测试机数据将“可操作”和“完全加载”分开：10,000 件重复零件冷加载约 0.57 秒可操作、6.70 秒完全加载；10,000 件／2,000 种定义冷加载约 0.70 秒可操作、39.21 秒完全加载，热缓存约 0.57 秒和 12.26 秒。保存约 0.50–0.61 秒。这些是固定测试机与工程的数据，不是所有电脑的保证值。

剩余差距：2,000 件／2,000 定义冷加载时的拖动预览脚本平均为 9.40 毫秒／帧，超过 8 毫秒目标；10,000 件重复定义冷加载 BOM 约 541.20 毫秒，略高于 500 毫秒参考线。保持检查开启，等待形状及检查完成后再核对交付文件。

## 反馈时附上什么

1. 说明版本、当前数据包名称与版本、操作入口和最短重现步骤。
2. 附上相关报告、问题零件编号、预期与实际结果。截图可用“视图 → 导出截图”取得模型画面。
3. 提供可以公开分享的最小工程；删除与问题无关的敏感参考图、对话及个人路径。不要附上密钥、令牌或账户凭据。
